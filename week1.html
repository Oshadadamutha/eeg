Week 1 – Data Ingestion & Signal Processing Pipeline

Objective

The objective of this week was to decode complex physiological EEG datasets and transform them into a clean, structured, and GPU-ready format suitable for deep learning pipelines. This stage laid the foundation for all subsequent CNN-based motor imagery classification experiments.

Dataset Challenge

The project utilized the MindBigData Motor Imagery EEG Dataset. The dataset was stored in MATLAB v7.3 format which internally uses the HDF5 standard. Each file contained deeply nested hierarchical objects that prevented direct NumPy loading.

The dataset consisted of six motor imagery classes:

Left Right Forward Backward Up Down


Files followed the naming pattern:

MoveSep_session*_sub*_reaching_MI.mat

Each file contained multiple EEG trials recorded across 60 channels with high-resolution temporal sampling, resulting in several gigabytes of raw data distributed across multiple sessions and subjects.

Custom Data Parser – dataLoaderNew.py

A fully customized parser was implemented to traverse nested HDF5 groups safely and extract the raw EEG arrays. The parser decodes variable-depth MATLAB structures and converts them into uniform tensors.

  • Loaded HDF5 objects using h5py.
  • Traversed dynamic object references and groups.
  • Extracted EEG signals in the format:
(Trials, Time_Samples, Channels)

This structure allowed seamless concatenation of trials across multiple sessions and subjects while preserving channel order and temporal resolution.

Tensor Standardization for CNN

To enable convolutional neural networks to operate on EEG signals, the extracted data was standardized into the following tensor shape:

(N, 1, 60, 2500)
  • N – number of trials.
  • 1 – artificial depth channel.
  • 60 – EEG electrode channels.
  • 2500 – time samples per trial.

This representation treats EEG as a 2D image, where spatial relationships between electrodes and temporal dynamics can be jointly learned using 2D convolutional kernels.

Class Balancing Strategy

To eliminate dataset bias, trials were aggregated across multiple session and subject files. This ensured that each motor imagery class had equal representation across the dataset.

  • Merged trials across all sessions.
  • Trimmed over-represented classes.
  • Validated final class distribution.

Final Outcome

A memory-efficient torch.utils.data.Dataset wrapper was developed, enabling real-time batch streaming to GPU memory during training. This abstraction hides all file I/O and preprocessing complexity from the model training stage.

  • GPU-ready batch streaming.
  • Low RAM footprint.
  • Fully compatible with PyTorch training loops.
