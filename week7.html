01 / The Splitting Decision

The most consequential architectural decision of Week 7 was not about the neural network itself — it was about how we evaluate it. Session-based evaluation had been masking a deeper problem: the model couldn't generalize even within the same recording session.

❌ Previous Strategy

Session Split

Train on Sessions 1–2, evaluate on Session 3. Tests cross-session domain adaptation before we've confirmed basic learnability.

Result: ~40–45% accuracy (near-chance)
✓ New Strategy

Randomized 70/15/15

Shuffle all trials across all sessions. Splits 70% train, 15% validation, 15% test. First verify the model can learn at all.

Result: Measurable learning signal observed

This separation of concerns is critical: it decouples the Learnability Problem (can the model learn from EEG at all?) from the Domain Adaptation Problem (can it generalize across sessions?). We must solve them in order.

02 / The Training Pipeline

01

Adam Optimizer @ 3e-4

Karpathy's Constant — empirically optimal for most deep learning tasks. Adaptive moment estimation handles the sparse EEG gradient landscape.

02

StepLR Scheduler (step=8, γ=0.5)

Halves the learning rate every 8 epochs. This "annealing" drives the model into sharper loss minima as training matures.

03

Validation Monitoring

Validation accuracy is computed every epoch. Tracks generalization — not just training fit — in real time.

04

Best-Model Checkpointing

Saves best_thinNet.pth only when val_acc improves. Prevents the "Last Epoch Bias" from late-stage overfitting.

# train_cnn.py — Core training loop
optimizer = optim.Adam(model.parameters(), lr=3e-4)
scheduler = optim.lr_scheduler.StepLR(optimizer, step_size=8, gamma=0.5)
best_val_acc = 0.0

for epoch in range(EPOCHS):
    model.train()
    for X, y in train_loader:
        optimizer.zero_grad()
        loss = criterion(model(X), y)
        loss.backward()
        optimizer.step()

    val_acc = evaluate(model, val_loader)
    if val_acc > best_val_acc:
        best_val_acc = val_acc
        torch.save(model.state_dict(), 'best_thinNet.pth')
    scheduler.step()

03 / Limitations Identified

⚠ Known Issue — Loss Function Mismatch

During Week 7 testing, a critical inconsistency was identified: thinNet outputs raw logits, but train_cnn.py applies NLLLoss, which mathematically requires log-probabilities (the output of LogSoftmax). While PyTorch's numerical stability mechanisms prevent training from completely breaking down, the gradient signal is theoretically incorrect. This mismatch is scheduled for resolution in Week 8 by replacing NLLLoss with CrossEntropyLoss, which handles the softmax internally.
