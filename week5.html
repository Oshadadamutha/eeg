The Leakage Problem Critical

Statistical leakage is the most insidious bug in machine learning pipelines. When Z-score normalization statistics (mean μ and standard deviation σ) are computed across the entire dataset before the train/test split, the model implicitly learns about the test distribution. Evaluation metrics appear artificially high — a false victory that collapses at deployment.

❌ Weeks 1–4 (Broken)

Global Normalization

Compute μ, σ on ALL data including test set. Test data "leaks" into normalization. Model implicitly knows test distribution. Metrics are dishonestly optimistic.

⟶
✓ Week 5 (Fixed)

Train-Only Stats

Compute μ, σ using ONLY training data. Apply same transform to val/test. Zero look-ahead bias. If test data has different scale, model must handle it robustly — reflecting reality.

The solution is a two-phase pipeline: first compute statistics using only the training directory, then apply those frozen statistics to all splits. The compute_train_stats function encapsulates this critical boundary.

// Data Pipeline — Fit on Train, Transform All
Step 1 →
Iterate ONLY through /Train directory
Step 2 →
Compute channel-wise μ, σ → freeze these stats
Step 3 →
Apply frozen μ, σ to /Train → Z-scored train set
Step 4 →
Apply same frozen μ, σ to /Val → Z-scored val set
Step 5 →
Apply same frozen μ, σ to /Test → Z-scored test set
def compute_train_stats(train_folder):
    """
    Compute channel-wise mean and std using ONLY TRAIN data.
    This guarantees zero leakage into validation/test sets.
    """
    all_data = []
    for fname in os.listdir(train_folder):
        if fname.endswith('.mat'):
            with h5py.File(os.path.join(train_folder, fname), 'r') as f:
                for key in ['left', 'right']:
                    data = np.array(f[key])  # (Trials, Time, Channels)
                    data = data.transpose(0, 2, 1)  # → (Trials, Channels, Time)
                    all_data.append(data)

    all_data = np.concatenate(all_data, axis=0)
    mean = all_data.mean(axis=(0, 2))  # shape: (Channels,)
    std  = all_data.std(axis=(0, 2))   # shape: (Channels,)
    return mean, std  # ← Frozen. Never recalculated.

HDF5 Ingestion & Dimensional Transposition Engineering

Raw data arrives in MATLAB v7.3 format (accessed via h5py) with a dimensional ordering that is incompatible with PyTorch's convolutional layer expectations. A mandatory transposition step corrects this at load time.

with h5py.File(filepath, 'r') as f:

    data = data.transpose(0, 2, 1)       # → (Trials, Channels, Time) ✓
    data = data[:, np.newaxis, :, :]         # → (Trials, 1, Channels, Time) ✓

# Z-score normalization using frozen train stats
data = (data - mean[np.newaxis, np.newaxis, :, np.newaxis]) / \
        (std[np.newaxis, np.newaxis, :, np.newaxis] + 1e-8)

Outcome: Drop-then-Stabilize Effect Result

The immediate effect of removing leakage was a drop in reported accuracy — not because the model got worse, but because previous metrics were dishonest. After implementing the correct pipeline, accuracy stabilized at its true baseline, providing a valid foundation for all future improvements.

Initial Impact — Accuracy Drop

Previously inflated "cheating" accuracy dropped when test leakage was removed. This initially appears negative but is the correct outcome — it reveals the true difficulty of the task.

Long-term Benefit — Valid Benchmarking

Every accuracy number from Week 5 onwards represents genuine generalization capability. Improvements in later weeks (Weeks 8–10) are now trustworthy and attributable to specific architectural decisions.
